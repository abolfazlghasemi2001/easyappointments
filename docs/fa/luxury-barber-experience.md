# تجربهٔ آرایشگاه: راهنمای طراحی و وضعیت اجرا

این سند، بخش‌هایی را که در این تغییر پیاده‌سازی شده‌اند و محدودیت‌هایی را که عمداً با دادهٔ ساختگی پنهان نشده‌اند، ثبت می‌کند.

## طراحی و تایپوگرافی

- متغیرهای رنگی و spacing در `assets/css/brand.scss` تعریف شده‌اند؛ پالت کرم/مشکی/طلایی، focus ring، فرم‌ها، کارت‌ها و حالت تاریک از یک منبع استفاده می‌کنند.
- Vazirmatn و Estedad از npm در build کپی می‌شوند و در Production از همان سرور ارائه می‌شوند؛ درخواست فونت به CDN خارجی نداریم. مجوز OFL فونت Estedad نیز کنار فایل‌ها کپی می‌شود.
- انیمیشن‌ها CSS-first هستند، برای حالت `prefers-reduced-motion` خاموش/کوتاه می‌شوند و از dependency انیمیشن خارجی استفاده نمی‌کنند.

## تجربهٔ نوبت‌گیری

- صفحهٔ رزرو یک Hero تصویری و بخش‌های خدمات/تیم دارد. نام، مدت، قیمت، ارز و افراد تیم از رکوردهای واقعی Easy!Appointments می‌آیند.
- انتخاب کارت خدمت، همان خدمت را در فیلد اصلی انتخاب می‌کند؛ انتخاب آرایشگر نیز خدمات قابل ارائهٔ او را اعمال می‌کند. منبع حقیقت همچنان selectها و endpointهای اصلی رزرو هستند.
- کاروسل‌ها با CSS Scroll Snap و JavaScript کوچک و بدون dependency پیاده شده‌اند: دکمه، dot، صفحه‌کلید، touch، pause روی hover/focus، و توقف هنگام باز بودن تور. حرکت خودکار برای reduced-motion غیرفعال است.
- تاریخ در تقویم موجود جلالی نمایش داده می‌شود و مقدار Gregorian موردنیاز API دست‌نخورده می‌ماند.
- صفحهٔ موفقیت یک confetti کوتاه دارد؛ دادهٔ نوبت/مشتری در Service Worker cache نمی‌شود.

## Spotlight و کمک درون‌برنامه‌ای

- پیاده‌سازی بدون کتابخانه در `assets/js/utils/spotlight-tour.js` قرار دارد. Tooltip واکنش‌گراست، عنوان/توضیح/پیشرفت را اعلام می‌کند، focus را مدیریت می‌کند، با Escape بسته می‌شود و با کلیدهای راست/چپ/Enter قابل‌استفاده است.
- وضعیت تور در `localStorage` با کلیدهای `tour-completed`, `tour-step`, `tour-skipped` و نگاشت شناسهٔ تور ذخیره می‌شود. «بعداً» مرحله را برای Resume نگه می‌دارد و «رد کردن» را با تکمیل اشتباه نمی‌گیرد.
- تورهای `onboarding`, `booking`, `admin` و `provider` تعریف شده‌اند. در حالت دستی، تور از دکمهٔ راهنما دوباره اجرا می‌شود.

## آیکون‌ها

- ۶۰ آیکون SVG line-art در `assets/img/icons/` قرار دارد: ۱۵ ابزار آرایشگاه، ۱۵ عملیات، ۱۵ ناوبری و ۱۵ وضعیت. هر فایل مستقل است و sprite مشترک هم برای استفادهٔ inline با `currentColor` موجود است.
- بازسازی مجموعه: `python3 scripts/generate_barber_icons.py`.

## حالت تاریک و PWA

- انتخاب روشن/تیره با `localStorage` حفظ می‌شود و `data-bs-theme` بوت‌استرپ را به‌روز می‌کند.
- `manifest.webmanifest` و Service Worker اضافه شده‌اند. Worker فقط دارایی‌های static هم‌مبدأ را cache می‌کند؛ پاسخ HTML، API، مسیرهای login و دادهٔ خصوصی نوبت‌گیری هرگز وارد cache نمی‌شوند.

## مرزهای آگاهانه

- دیتابیس فعلی schema نظرات مشتری یا گالری قبل/بعد ندارد. این رابط، نظر جعلی، امتیاز ساختگی یا عکس قبل/بعد را به‌عنوان کار واقعی نمایش نمی‌دهد. برای فعال‌سازی این بخش‌ها ابتدا باید منبع داده و پنل مدیریت محتوای واقعی اضافه شود.
- پرداخت زرین‌پال به‌دلیل نداشتن Merchant ID، سیاست بازپرداخت/لغو و گردش‌کار تأیید مالی در این مخزن فعال نشده است. افزودن دکمهٔ پرداخت بدون backend idempotent و تأیید callback در سمت سرور امن نیست.
- TLS روی سرور واقعی، صدور گواهی، صحت DNS، Lighthouse و بازیابی backup فقط پس از استقرار روی سرور/دامنهٔ واقعی قابل اندازه‌گیری‌اند. فایل‌های Production آماده شده‌اند اما این محیط دسترسی به سرور کاربر ندارد.

## بررسی محلی

```bash
npm ci
npm run test:js
npx gulp compile
```

تست‌های JavaScript تاریخ جلالی و وضعیت/focus/persistence تور را اجرا می‌کنند. برای lint و تست PHP از PHP/Composer یا محیط php-wasm پروژه استفاده کنید.
